- **Environment:** one EC2 t3.large in ap-south-1.
- **Model:** Amazon Nova Lite through `apac.amazon.nova-lite-v1:0`.
- **Test run:** `20261026-215301` (timestamped in UTC; 27 Oct in IST). The full, unedited summary is in [results/2026-10-27-SUMMARY.md](results/2026-10-27-SUMMARY.md), with the AWS account and instance IDs masked.

## Normal run

A helpdesk question produced 3 model calls (615/87, 777/73 and 900/88 input/output tokens) and 2 tool calls (search 5 ms, comment 4 ms). All returned 200 and were attributed to `helpdesk-bot`.

- The agent saw 3 of the 5 tools.
- The gateway added 4–5 ms per tool call; each model call took about 0.7–0.8 s in Bedrock.
- The whole run cost a fraction of a cent.

## Findings

None of these let an agent reach a tool, model, secret or project it was not granted.

| # | Finding | Risk | What to do |
|---|---|---|---|
| 1 | An injected prompt steered a granted write tool (test 3) | Unwanted writes inside the allowed scope | Grant write tools narrowly; Bedrock Guardrails; human approval for writes |
| 2 | A disabled connector's tools stay listed for up to 10 minutes (test 10). Tool lists come from a cache that a connector update does not clear; calls check the enabled flag directly | Confusing during an incident | Delete the connector for an instant, visible cut; raise with Tuskira |
| 3 | The token cap applies only when a request states a size (test 8) | An agent gets the model's default output length by omitting `maxTokens` | Rely on budgets for spend; raise with Tuskira |
| 4 | The brute-force lockout is per source IP (test 7) | One bad client locks out every agent behind the same NAT or load balancer | Set `GATEWAY_API_TRUSTED_PROXIES` so the gateway sees real client IPs |
| 5 | Agent keys can read every profile and list log rows (test 11). The built-in `agent` role includes `*.read` | An agent learns the whole policy and other agents' activity | Redefine `agent` as `mcp.*`, `llm.*` through `auth.roles` in the gateway's YAML config (test this before relying on it) |
| 6 | Another key in the same tenant can end an agent's session (test 14) | Disruption only; needs the 32-byte session ID | Low risk; one tenant per trust boundary |

**Other observations:**
- The admin API reports a blocked redirect during discovery as a generic `internal error`. Admins have to read the gateway log to see why.
- From an India-billed account, Claude on Bedrock failed AWS Marketplace's payment check (`INVALID_PAYMENT_INSTRUMENT`). Nova Lite worked after one IAM change.

## Not covered

These were on the gap list but are not scripted:
- a `viewer` key or a key without `mcp.access` calling tools;
- a new key with no profile (`REQUIRE_PROFILE`);
- `X-Forwarded-For` spoofing against the lockout;
- requests-per-minute limits;
- oversized and concurrent requests;
- tool-description changes after discovery (tool poisoning);
- PII in captured prompts;
- fail-closed behaviour with the gateway stopped;
- ClickHouse down;
- audit of policy changes;
- keys and credentials at rest in Postgres;
- streaming calls;
- restart and upgrade.
